================================================================================
PRÉSENTATION DU PROJET
================================================================================

ENSO Monitor est une application web de visualisation des données climatiques
basées sur l'indice ONI (Oceanic Niño Index) publié officiellement par la NOAA.

L'indice ONI mesure les anomalies de température de surface de la mer dans le
Pacifique équatorial central. Il permet de détecter et classifier les phases :
  - El Niño  : ONI >= +0.5°C pendant au moins 5 saisons consécutives
  - La Niña  : ONI <= -0.5°C pendant au moins 5 saisons consécutives
  - Neutre   : entre ces deux seuils

Utilisateurs cibles : scientifiques, étudiants en climatologie, curieux du climat.

Fonctionnalités prévues :
  - Import automatique des données ONI depuis la NOAA (ETL)
  - Stockage en base de données PostgreSQL
  - API REST (FastAPI) exposant les données
  - Interface web (React) avec graphiques interactifs

ARCHITECTURE TECHNIQUE
================================================================================

STACK :
  Frontend  : React 18 + TypeScript + Vite
  Backend   : Python 3.11 + FastAPI + Pydantic v2
  Base BDD  : PostgreSQL 15 + SQLAlchemy 2 + Alembic
  ETL       : Pandas + NumPy + Requests
  Tests     : Pytest (backend/etl) + Vitest (frontend)
  Versioning: Git + GitHub

STRUCTURE DES DOSSIERS :
  enso-monitor/
  ├── backend/
  │   ├── app/
  │   │   ├── models/      → Modèles SQLAlchemy (tables BDD)
  │   │   ├── schemas/     → Schémas Pydantic (validation données)
  │   │   ├── routers/     → Routes FastAPI (endpoints API)
  │   │   ├── services/    → Logique métier (traitement données)
  │   │   └── main.py      → Point d'entrée de l'API
  │   ├── tests/           → Tests Pytest du backend
  │   └── requirements.txt → Dépendances Python du backend
  ├── etl/
  │   ├── tests/           → Tests Pytest de l'ETL
  │   └── requirements.txt → Dépendances Python de l'ETL
  ├── frontend/            → Application React (initialisée à l'étape suivante)
  ├── infrastructure/      → Fichiers Docker, docker-compose (à venir)
  ├── docs/
  │   └── diagrams/        → Schémas d'architecture (à venir)
  ├── Documentation.txt    → CE FICHIER
  ├── README.md            → Présentation courte + instructions
  └── .gitignore

POURQUOI CETTE ARCHITECTURE :
  - Séparation claire des responsabilités (backend / etl / frontend)
  - L'ETL est indépendant du backend : il peut tourner séparément (cron, script)
  - Les __init__.py dans backend/etl permettent à Python de reconnaître
    les dossiers comme des packages importables
  - Les .gitkeep maintiennent les dossiers vides dans Git
    (Git ne versionne pas les dossiers vides nativement)

================================================================================
INSTALLATION ET LANCEMENT
================================================================================

Prérequis système :
  - Python 3.11+  → vérifier : python3 --version
  - Node.js 18+   → vérifier : node --version
  - PostgreSQL 15+ → vérifier : psql --version

Cloner le projet :
  git clone https://github.com/Baba77DRAME/Enso-Monitor.git
  cd Enso-Monitor

Backend (à faire à l'étape 2) :
  cd backend
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements.txt
  uvicorn app.main:app --reload
  # API disponible sur http://localhost:8000
  # Doc Swagger   sur http://localhost:8000/docs

Frontend (à faire à l'étape 3) :
  cd frontend
  npm install
  npm run dev
  # Interface disponible sur http://localhost:5173

ETL (à faire à l'étape 6) :
  cd etl
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements.txt

Tests backend :
  cd backend
  source .venv/bin/activate
  pytest

Tests frontend :
  cd frontend
  npm run test
